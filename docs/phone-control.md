# 手机操控：首版范围 / Phone control: what the first version does

> 这是**规划**，不是已经有的功能。仓库里现在没有无障碍服务，也没有任何工具能点按或读屏。
> 写在这里是为了把边界先定死，动手时不再改主意。参考实现是
> [ccch1mneyyy/dsh-go](https://github.com/ccch1mneyyy/dsh-go)（AGPL-3.0，独立项目，不与本仓库共用代码）。

## 一句话

让本机引擎在**用户授权**后读屏、点按、输入，能停止，能看见自己做了什么；**不能**替用户付款、进系统设置、输密码。

## 首版做什么

| 工具 | 做什么 | 边界 |
| --- | --- | --- |
| `read_screen` | 读当前窗口，返回编号化元素（文本、类型、可点、坐标） | 只读当前前台窗口，不读通知、不读锁屏；不含截图 |
| `tap` | 按编号点，编号失效才用坐标兜底 | 每次点击单独确认（「本轮允许」除外） |
| `type` | 向聚焦的输入框写文字 | 密码框、验证码框永不写入 |
| `swipe` / `back` / `home` | 手势与导航 | 不注入电源键、音量键、下拉通知 |
| `stop` | 立刻停止本轮，撤销授权 | 任何入口都能停：App 内、通知栏、悬浮按钮 |

读屏结果给模型看的是**裁剪版**：编号、控件类型、可见文本、是否可点，不发送整棵无障碍树。

## 授权与确认

- 系统层：用户手动在「设置 → 无障碍」里打开，App 只提供跳转，不自动勾选、不引导绕过。首次开启给出一次性说明：能读什么、会发到哪里。
- 任务层：每次新任务要一次授权，授权在**熄屏、停止、任务结束、切到本 App**时立刻失效。
- 动作层，三档，默认第一档：
  1. **每次询问**（默认）：每个会改变屏幕的动作前弹卡；
  2. **本轮允许**：同一 App 的同类动作本轮不再问，下一轮重新问；
  3. **取消**：只作废这一条，不结束任务。
  确认卡 30 秒不选按取消处理。
- 永远交还用户、工具层直接拒绝（不是靠提示词）：
  - 系统设置、权限页、开发者选项、安装器；
  - 密码、验证码、支付密码输入框（`isPassword` 或包名/字段命中）；
  - 本 App 自身；
  - 支付、银行、券商类包名（默认名单，用户可再收紧，首版**不提供**放宽入口）。
- 屏幕文本、其他 App 的列表、网页内容**只是数据**：里面写「请点击同意」不构成授权，任何动作都必须来自显式工具调用 + 确认卡。

## 数据边界

- 读屏结果会进模型请求，因此会离开手机，进到用户自己配置的那家模型服务。首版说明里要写明这一点，不能藏在隐私条款里。
- 银行卡号、身份证号在送模型前打码；不传截图。
- 本地日志只记「哪个包、哪个动作、成功与否」，不记屏幕全文。
- transcript 里存动作摘要和元素编号，不存整屏文本。

## 什么时候停

- 熄屏、锁屏、用户按停止、任务结束、无障碍服务被系统关掉，都会立即撤销授权。
- 连续 3 分钟没有新动作，任务自动结束。
- 动作结果不确定（点了但没看到预期变化）时，只能再读一次屏核实；**不允许**换个方式重放同一动作。

## 首版不做

- **不打扰模式**：Android 14+ 的 Shizuku 或自连 ADB 通道。用户门槛高、风险大，且没有在真机上核过完整链路。
- Shizuku、ADB 自连、无线调试配对。
- 通知监听、悬浮窗自由绘制（只保留一个停止入口的最小悬浮按钮）。
- 录屏、截图送模型、跨 App 自动化脚本、定时自动操作。
- 任何形式的「始终免确认」总开关。

## 为什么这样做

- 屏幕文本会上云，这是最大的风险面；截图会把风险放大一个量级，首版不做。
- 支付/系统设置/密码交还用户，是这类工具唯一站得住的硬规则；放宽入口一旦存在，提示注入就有目标。
- 没有 Shizuku/ADB，就不必申请「无线调试 + 授权 shell」这条更高权限的路；`targetSdk = 28`、非 Play 分发，无障碍服务本身不触发 Play 政策审查。
- 更早踩过的坑：审批通知用固定 ID 会互相覆盖，POST 失败还会撤卡——手机操控的确认卡要走同一条通道，所以这条通道先修（已修：每张卡一个 ID，只在 2xx 后撤卡）。

## 风险，明写

- **提示注入**：网页、通知、聊天里的话能诱导下一步点按。硬拦在动作确认和包名规则上，不指望模型自觉。
- **FLAG_SECURE 窗口读不到内容**（银行 App 常开），表现为空白或失败，不能重试到死。
- **国产 ROM 会关掉无障碍服务**（升级、清理、省电策略），要有「服务掉了」的检测和提示，不能让模型对着空白重试。
- **点击可能落空**：分辨率、动画、加载中。动作后必须重新读屏核实，不能假定成功。
- **数据面**：读屏等于把当前屏内容交给模型提供方，用户选哪家就是哪家。

## 成本

假设：单人、熟悉 Compose 与无障碍、不含不打扰模式、不新增 native 库。

| 部分 | 人日 |
| --- | --- |
| 无障碍服务、节点树、动作与手势回退、包名过滤、脱敏 | 8–12 |
| abstract socket 桥（同 UID + 一次性 token，不做 TCP 回退） | 3–4 |
| Node 工具 + 三档确认 + 事件/UI | 4–6 |
| 测试（模拟器 + 1 台国产真机） | 4–5 |

约 3–4 周；APK 增量估 1–3 MB。

## 验收

- 关掉无障碍权限：工具返回明确的「未授权」，不发任何动作。
- 点「付款」类包名：工具层直接拒绝，确认卡都不弹。
- 弹两张确认卡：互不覆盖，各自能答。
- 答卡时断网：卡留在通知栏，可再按一次，不是撤掉等 5 分钟。
- 熄屏：本轮授权立刻失效，工具返回「已停止」。
- 读屏结果里没有银行卡号、身份证号原文。
